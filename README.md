Реализовано восстановление архитектуры по статье Zhang, Chen, Luo, *A comprehensive framework of synchronous SOC-SOH joint estimation for lithium-ion battery with multi-depth expert networks*, Energy 339 (2025), 138953, DOI: 10.1016/j.energy.2025.138953 (`PINN.pdf`). Это MDEN с обучаемым взвешиванием ошибок SOC/SOH. Физическая невязка дифференциального уравнения в loss статьи отсутствует.

**Запуск**

1. Распакуйте архив в отдельный каталог проекта и откройте основной ноутбук из него.
2. В окружении Jupyter с подходящей для вашей GPU сборкой PyTorch установите проект: `python -m pip install -e '.[notebook,test]'`. Минимум Python 3.10 и PyTorch 2.4. Набор фактически проверенных версий записан в `docs/VALIDATION.json`; вся комбинация минимальных версий отдельно не тестировалась.
3. Перезапустите kernel, чтобы удалить из памяти старые импорты.
4. Укажите `RAW_DATA_DIR`. Выберите `DATASET_CELL_LIMIT = 10`, `30` или `50`, либо `TARGET_RAW_GB = 10.0` для отбора по объёму исходных CSV. Split и имя кеша вычисляются автоматически.
5. При фиксированном batch задайте `FIXED_MICRO_BATCH_SIZE = 512` или другой размер, который помещается на вашей GPU. При `None` запускается измерение пропускной способности. Размер batch влияет и на число обновлений optimizer.
6. Задайте `MONITOR` до обучения: `loss`, `rmse_soc`, `rmse_soh` или `balanced_rmse`. По умолчанию — `balanced_rmse`. Loss остаётся совместным, с экспериментальной физической добавкой.
7. Проверьте новую диагностику физической согласованности TRAIN-меток. `PHYSICS_ENABLED=True` включает добавку; для контрольного запуска задайте `False`. Коэффициенты в YAML пока не откалиброваны на реальных данных.
8. Выполните все ячейки последовательно. Новые данные подготавливаются в кеш v8, результаты — в отдельный каталог `runs/mden_v3_...`.

**Кеш:** `CLEAN_OLD_PREPARED=True` удаляет старые поколения текущего кеша; `DELETE_PREPARED_AFTER_RUN=True` удаляет текущий кеш в последней ячейке, после test и графиков. Сначала сохраняются маленькие файлы подготовки в `runs/.../data_recipe/`. Исходные CSV и результаты обучения сохраняются. Для повторной работы с окнами без пересоздания задайте `DELETE_PREPARED_AFTER_RUN=False`. После прерывания очистите кеш скриптом `scripts/cleanup_prepared.py`; без `--apply` он только показывает кандидатов. Не запускайте очистку, пока работают старые версии программы без блокировок.

В каждом новом запуске сохраняются `last.pt`, `best_joint.pt`, `best_soc.pt`, `best_soh.pt`, `best_balanced.pt`, история, test-метрики по каждому горизонту, графики и CSV для двух примеров каждого split. Test оценивается по выбранному заранее критерию `MONITOR`.

**Продолжение после остановки**

Укажите `RESUME_PATH` на `last.pt` этой редакции. Batch восстановится автоматически; параметры, состояние optimizer/scheduler/GradScaler и генераторов случайных чисел загружаются из checkpoint. Оставьте прежними данные, архитектуру, seed, AMP, gradient accumulation, clipping, начальные LR/weight decay, patience и monitor. `NUM_EPOCHS` — общее требуемое число эпох, его можно увеличить. Сохранение выполняется на границе эпохи: незавершённая эпоха после сбоя повторится.

Для продолжения используется `last.pt`. Старые audited v3 checkpoints можно загружать для инференса или продолжать с отключённой физикой и прежним monitor. Для включения физики нужен новый эксперимент: resume проверяет точное совпадение конфигурации loss. Удалённый кеш будет восстановлен из тех же неизменных CSV; исходный split/scaler должны совпасть. Более ранние checkpoints до аудита несовместимы с изменённой архитектурой. Численные результаты между разным оборудованием, способами вычисления и версиями CUDA/PyTorch могут отличаться даже при сохранённом RNG.

**Другие способы запуска**

Из корня установленного проекта:

```bash
python scripts/train_mden.py --raw-dir /path/to/cell_log_age --cells 50 --batch-size 512 --epochs 30 --monitor rmse_soc
python -m pytest -q
python scripts/smoke_notebook.py --in-process --work-dir /tmp/mden_notebook_check
```

Последняя команда создаёт искусственные CSV вне проекта и выполняет реальные ячейки ноутбука. Это проверка работоспособности, а не оценка точности на KIT. Для проверки в настоящем Jupyter kernel уберите `--in-process` в среде, разрешающей локальные соединения ядра.
